Nothing here needs App Review or Business Verification: with Standard Access, the Page answers the accounts that hold a role on the app (the team, up to 50 testers), which is all the video needs. ## Part 2: the webhook and the live test

1. **Verify token.** A random string of 20 characters or more (`openssl rand -hex 16`), stored as `MESSENGER_VERIFY_TOKEN`. The agent types it into the dashboard: a paste from the system clipboard does not reach the page through the automation, and `navigator.clipboard` is blocked on developers.facebook.com by a permissions policy.
2. **A public https address.** On the laptop, a second server instance, `PORT=3001 HOST=127.0.0.1 node --import=./lib/credentials.js src/server.js`, behind a quick tunnel, `cloudflared tunnel --url http://localhost:3001` (a random `trycloudflare.com` host that changes whenever the process ends; enter the new one in step 3 then). The `make server` instance on 3000, which other sessions drive, is never restarted; the 3001 instance is restarted after every `make secrets-set`. Later, the production host (`https://heyprudence.com` once its tunnel runs, `_product/docs/ops.md`) after `make deploy`.
3. **Configure webhooks.** Messenger API Settings → 1. Configure webhooks: Callback URL `https://<host>/api/messenger/webhook`, Verify token = `MESSENGER_VERIFY_TOKEN` → **Verify and save**. Meta's handshake GET arrives within a second, carrying both `hub.mode`/`hub.verify_token`/`hub.challenge` and `hub_mode`/`hub_verify_token`/`hub_challenge` in the same query string; the server answers it with the verify token alone, so this works before any Page is connected. Verified on Nov 4: step 1 ticked.
4. **Test.** With the App Secret stored and the instance restarted: from the vladztools account (Administrator), open `https://m.me/139962502991539` and send "hello": the typing dots, then a reply within seconds. Then long-press one of the stranger's messages → More → **Forward** → Hey Prudence; if the Page is not offered as a target, send a screenshot of the chat instead (same verdict, read by Muse Spark).
5. **Compare.** The first live delivery is checked against the assumptions in `_product/specs/messenger-channel.md` (Open questions): the attachment host and URL lifetime, the audio container of a voice message, and whether the Send API accepted the token in the `Authorization: Bearer` header (an error 190 or 104 on the first reply means it wants `?access_token=`: a one-line change in `src/channels/messenger.js`).

## What the Page cannot do yet

- Answer anyone without a role on the app: App Review for `pages_messaging` (a screencast) plus Business Verification, after the hackathon.
- Answer anything while `MESSENGER_APP_SECRET` is unset: every delivery is refused with 403, by design.
- Reply outside the 24-hour window the person's own message opens (the bot only ever replies, so this never bites).
- Know who the sender is: no account matching, no life context, nothing stored.
