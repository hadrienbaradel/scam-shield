## Contracts (code against these exactly)

### C1, images in `lib/llm` (agent `ads-engine`)
```js
import { generateImage, editImage, imageConfigured, imageModel, imageLabel } from "../llm/index.js";
await generateImage({ prompt, size = "1080x1350", n = 1, format = "jpeg", signal, provider, fetchImpl })
await editImage({ prompt, images: [{ bytes, mime }], size, format = "jpeg", signal, provider, fetchImpl })
// both -> { images: [{ bytes: Buffer, mime: "image/jpeg" }], model, provider, label }; throw on failure (message names the provider, the HTTP status and the API's own message, never a key)
imageConfigured(name?) -> boolean; imageModel() -> "muse-image-1.0"; imageLabel() -> "Muse Image 1.0"
```
`IMAGE_PROVIDER` (`meta` default, `openai` = any OpenAI-style `/images/generations` and `/images/edits`, `mock`), `IMAGE_MODEL`, `IMAGE_BASE_URL`. `meta` reads `META_MODEL_API_KEY` and `META_MODEL_BASE_URL` like the chat adapter; `openai` reads `OPENAI_API_KEY` (edits as multipart, the OpenAI way). The shared mock gains `mock.scriptImage(...)` (a Buffer, an Error or a function `(request, n)`), `mock.imageCalls`, cleared by `mock.reset()`; unscripted it returns a tiny valid JPEG.

### C2, the studio in `lib/ads/studio.js` (agent `ads-engine`)
```js
// words: { headline, primary_text, description, cta: "LEARN_MORE" | "SIGN_UP", photo_brief, landing: { headline, lead } }
// check: { pass, problems: [string], fixed: [string], summary, model }   summary is the card's line (L4)
proposeIdeas({ brief, count = 3, signal })        -> { ideas: [words], model }       // L2, L3: refused ideas are rewritten once, then dropped with a reason
makePhoto({ words, signal })                      -> { photo: { bytes, mime }, check, models: { image, check }, photosMade }  // L4: generate, check, at most one fix, check again
editIdea({ words, photo, instruction, signal })   -> { words, photo, check, changed: { words, photo }, models, photosMade }  // L5
checkPhoto({ photo, words, signal })              -> check
validateWords(words)                              -> { ok, problems: [string] }   // L3 in code: numbers outside the fact sheet, brands from lib/brands.js BRANDS, quotes, "guarantee", prices, length caps, cta list
export const PHOTO_COST_USD = 0.01;
```
Words and checks go through `complete` from `lib/llm/index.js` with a JSON schema (`json: { name, schema }`), the photo sent as an image part. Prompts and the fact sheet live in `prompts/ad-studio.md` (sections the code reads by heading), facts copied from `README.md` / `_product/marketing/submission.md` with their source.

### C3, ad networks in `lib/ads/networks/` (agent `ads-facebook`)
```js
import { getNetwork, networkNames } from "../ads/networks/index.js";   // networkNames() -> ["facebook"]
const fb = getNetwork("facebook");
fb.label                                   // "Facebook"
fb.configured() -> boolean; fb.missingKeys() -> ["META_ADS_TOKEN", ...]
fb.settings() -> { daily, currency, days, countries, ageMin, ageMax, launchStatus, budgetLabel: "$5 a day · 7 days" }
await fb.publish({ name, words, photo: { bytes, mime }, link, campaignId, signal, fetchImpl })
  -> { campaignId, campaignCreated, adsetId, creativeId, adId, imageHash, status, adsManagerUrl, budget: { daily, currency, days, endsAt } }
await fb.setStatus({ adId, adsetId, status: "PAUSED" | "ACTIVE", signal, fetchImpl })
await fb.review({ adId, signal, fetchImpl }) -> { state: "in_review" | "active" | "rejected" | "paused" | "other", effectiveStatus, reasons: [string] }
// errors: class AdNetworkError extends Error { step, status, code } with a plain message, no token, no URL with a token
```
Keys: `META_ADS_TOKEN` (system-user token with `ads_management`), `META_AD_ACCOUNT_ID` (`act_<digits>`; digits alone accepted), `META_ADS_PAGE_ID` (falls back to `MESSENGER_PAGE_ID`), optional `META_ADS_GRAPH_VERSION` (default the Messenger adapter's `v26.0`), `ADS_DAILY_BUDGET` (5, in the ad account's currency), `ADS_DAYS` (7), `ADS_COUNTRIES` (`US`), `ADS_AGE_MIN` (35), `ADS_AGE_MAX` (64), `ADS_LAUNCH_STATUS` (`ACTIVE`, or `PAUSED`).

### C4, the store, the admin API and the console page (agent `ads-console`)
`src/ads/store.js` (all SQL on 012), `src/routes/ads.js` (admin only: `requireUser` + `requireAdmin` from `src/auth.js`, as `src/routes/adminDb.js` does), `public/admin/views/ads.js` (+ one nav entry in `public/admin/console.js`). Long work runs in the background in-process and the page polls (the console's auto-refresh): a request never waits for a model.
- `GET /api/admin/ads` -> `{ ads: [ad], today: { photos, costUsd }, network: { name, label, configured, missing, budgetLabel }, models: { words, image, configured } }`; `ad` = `{ id, code, status, brief, version, versions, words, check, models, review, external, budget, counts: { visits, requests }, error, rejectedReason, createdAt, publishedAt, photoUrl, previewUrl }`.
- `POST /api/admin/ads/ideas { brief, count }` -> 202 `{ ids }`: one `drafting` row per idea at once, each filled in the background (C2 `proposeIdeas` once, then `makePhoto` per idea), then `draft`, or `failed` with a plain error. Rows left `drafting` or `editing` for more than 5 minutes read as failed ("interrupted").
- `POST /api/admin/ads/:id/edit { instruction }` -> 202, `editing`, then a new version and `draft` again (L5); `POST /:id/undo` -> the version before.
- `POST /:id/publish` -> one atomic `draft -> publishing` (a second click gets 409 and creates nothing), C3 `publish` with the link `https://<host>/a/<code>`, the campaign from `ad_campaigns` (stored when `campaignCreated`), then `published` with `external`, `budget`, `review`; on failure back to `draft` with `error`.
- `POST /:id/pause`, `/:id/resume`, `/:id/refresh` (review state), `/:id/reject { reason }`.
- `GET /:id/photo?v=<n>` -> the image bytes, `cache-control: private, max-age=300`.
Code against C2 and C3 through small injectable seams (`app.adsDeps` or a `deps` argument) so tests run without the other agents' code; the coordinator wires the real modules.

### C5, the landing variant (agent `ads-landing`)
`src/ads/landingVariant.js` `renderVariant(indexHtml, { code, headline, lead })` -> the live `public/index.html` with the English block's `<h1 id="l-h1">` text and the `p.l-lead` that follows it replaced by escaped text, the page `<title>` too, and a hidden `variant` input in the English early-access form; nothing else changes. `src/routes/adLanding.js`: `GET /a/:code` serves it for a `published` or `paused` ad (an admin session sees any status with `?preview=1`; anyone else gets 404 for unknown or unpublished), counts one visit unless the request is a robot or link previewer (`facebookexternalhit`, `Facebot`, `bot`, `crawler`, `spider`, `preview` in the user agent), `?preview=1`, or an admin; never stores the query string (`fbclid`). `src/routes/earlyAccess.js`: accepts an optional `variant` (`^[a-z0-9]{8}$`, stored only when an ad with that code exists), `public/landing/landing.js` sends the hidden field when present, `public/privacy.html` says the request keeps which ad it came from. Same security headers and CSP as `/`.
