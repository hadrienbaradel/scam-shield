# Check something else (pasted text, picture, voice note, email file)
Status: Built · Last updated: 2026-10-29

## Why
Scams arrive by text, WhatsApp, pop-up and letter too. The senior (or the family member sitting next to them) must be able to check anything in one place with the same verdict screen.

## Behavior
1. "Check something" lets the user paste the words of a text message, WhatsApp or email, say who sent it (name, number or address) and tap "Check this"; the same verdict card appears, with Read aloud and Ask my trusted person.
2. "Or send a picture of it": a screenshot or photo (PNG, JPEG, WebP, up to 8 MB) is read by Muse Spark, transcribed word for word without judging, then checked like text. The picture is never kept. If no message is found, the app says so.
3. "Or an email file": a `.eml` downloaded from any webmail is parsed in memory and checked exactly like a Gmail message; its authentication is trusted only if Gmail visibly received it. The file is never kept.
4. "Or a voice message": a voicemail or voice note is written down, then judged like a text (lines 8 to 13).
5. Pasted, pictured and spoken messages are never stored; only the verdict is kept, so "Ask my trusted person" sends what is on screen at that moment.
6. When Muse Spark is not switched on, the picture button is replaced by "Checking pictures needs Meta's Muse Spark… please paste the words instead" (the voice button follows line 12); text and `.eml` checks still work with the rule detector.
7. Each check is rate-limited per person (30 text, 10 picture, 10 voice, 20 file checks per minute).
8. Voice: the senior taps "Choose a voice message" ("Choisir un message vocal") and picks a voicemail or voice note (any file the browser can play: m4a, mp3, ogg, wav); the page converts it on the device to 16 kHz mono 16-bit WAV and keeps at most the first 4 minutes. A file the browser cannot open gets "This recording could not be opened. Try another file." ("Cet enregistrement ne peut pas être ouvert. Essayez un autre fichier.").
9. The recording is sent once to be written down, by Meta's Muse Voice Transcribe (`muse-voice-transcribe-1.0`) by default, and the words are judged like a text from the channel "voice_transcript"; the card shows "What the voice message says" ("Ce que dit le message vocal") under the verdict. No words heard: "We could not hear any words in this recording." ("Nous n'avons entendu aucun mot dans cet enregistrement.").
10. Before anything leaves the server, it accepts only what the page makes: a RIFF/WAVE file of plain PCM, mono, 16 kHz, 16-bit, with sound data, at most 4 minutes and 8 MB. Anything else is refused with one plain message naming the problem (in English), and nothing is sent.
11. Neither the recording nor its words are kept anywhere: only the check row (verdict, channel "voice"), as for a pasted text.
12. Muse Voice Transcribe writes the words down whenever Meta's key is set, whatever model judges; otherwise the selected provider does if it can (an OpenAI-style endpoint's `/audio/transcriptions`, model `LLM_TRANSCRIBE_MODEL`, default `whisper-1`); Claude cannot. With none of them, the voice button is replaced by "Checking voice messages needs Meta's Muse Voice Transcribe, which is not switched on here yet." ("La vérification des messages vocaux nécessite Muse Voice Transcribe de Meta, qui n'est pas encore activé ici.").
13. When the transcription fails (a refused key, too many requests, a server error, no answer within 30 s), the senior sees "We could not listen to this recording right now. Please try again in a minute." (in English, on the French page too); nothing is judged or kept.

## Demo path
Paste "USPS: your package is on hold. Pay a $1.99 redelivery fee" with a link, show the red card; or drop a screenshot of a bank text and show the transcription turning into a verdict (needs the Muse key); or choose the "Grandma, it's me, I had an accident" voicemail file: the words appear under a red card (video 1:47–2:05, needs the Meta key). The seeded 15 s "it's Ethan" voicemail in demo mode is not built (Hadrien's row in `_product/log.md`).

## Out of scope
Live phone calls (never listened to), QR codes inside pictures (not decoded), PDFs, browser extension "check this page", links pasted alone without text (works, but judged as a bare link).

- Transcription in the model's language vs. the user's: a French screenshot checked by an English profile?
- Voice, checked against Meta's docs on 2026-10-29 (dev.meta.ai/docs/speech-to-text, /docs/api-reference/voice/transcribe, /docs/api-reference/voice/schemas, /docs/error-handling): `POST https://api.meta.ai/v1/asr/transcribe` with a bearer key; multipart `request` JSON plus `audio` WAV; `muse-voice-transcribe-1.0` is the only model id; `audioEncoding: "WAV"` is the only batch value (RIFF/WAVE, mono, 16-bit integer PCM, 16 or 24 kHz); `mode: "PUSH_TO_TALK"` (the default) makes the clip one turn; 10 minutes (400) and 32 MB (413) at most; 429 on the concurrency or hourly cap; 500 when processing fails (retry once); the JSON answer is `sessionId`, `transcript`, `audioDurationMs`, `turns` (empty in PUSH_TO_TALK), with no language field; `languageBias` takes language names ("English", "French") and only nudges; 25 languages including English and French. Nothing in our request needed fixing.
