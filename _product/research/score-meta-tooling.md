# Scoring higher on "Use of Meta AI Tooling" (25%): where we stand, candidates, plan (review, 2026-10-27)

Scope: what a judge credits under this criterion, what the video shows today, every candidate use of Meta tooling with lift, effort (two developers with Claude Code agents), demo line and risk, and the five to do. Facts were checked on 2026-10-27 against dev.meta.ai and the participant guide; "(unverified)" marks the rest. Rules: [hackathon.md](hackathon.md); API facts: [meta-ai-stack.md](meta-ai-stack.md); strategy and plan: [how-to-win.md](how-to-win.md); feasibility numbers: [feasibility.md](feasibility.md).

## How this rubric item is judged
- Official Rules (hackathon.md): 25%, scored 0–10 on "how creatively the team used Meta's AI tooling, whether they went beyond a basic integration, and whether they surfaced unexpected capabilities". Participant guide, verbatim: "How creatively did this team use Meta's AI tooling?", "Did they go beyond a basic integration?", "Did they surface capabilities that surprised even us?" Stage 1 gate: "reasonably used Meta Model API and/or Meta's open-weight models".
- What counts as tooling: "Use the Muse Spark series, Muse Wonder, Muse Image and SAM 3.1 through Meta Model API", "run Meta open weights models" (Muse Glimmer, Muse Spark Open), "code faster with Muse Code" (event page); the guide adds Muse Voice Transcribe. Anti-projects include "Simple Image Analyzers" and "Basic RAG Applications".
- What Meta is teaching this week: Agents 101 "Build a Multimodal AI Agent" (Oct 27), Agents 102 "Best Practices for Verifiable Agents" (Oct 28, Yash Khare; content not public yet, unverified), "Specialized Intelligence on Fireworks ... with Muse Open Models" (Oct 30). Meta's own cookbook names the patterns it likes: "Interleaved reasoning and tool use", an "Alert fatigue copilot" that is grounded, self-evaluating and strict-JSON, "Perception grounding", "Local agent that asks first" (Glimmer locally, Spark after sign-off). Verifiable, grounded, tool-using, strict output is the vocabulary to show.
- Mechanics: judges score from the 3-minute video, the repo and the live product; finalists are re-ranked by judges watching the video live. A capability counts only when it is on screen, named (model, API feature) and doing product work. The likely judges are Meta MSL/DevRel engineers (inference) who recognise "Responses API reasoning summary", "strict schema" and "url_citation" on sight.
- Bonus prizes that touch this item (guide, verbatim): Open Weight $10K for "Muse Glimmer or Muse Spark Open ... on participants' own hardware or through partner-provided inference", "The infrastructure partner verifies that the project runs on an eligible Meta open-weight model", "flagged during the first judging round"; Agentic $5K for "the strongest use of AI agents to complete meaningful tasks ... make decisions, or coordinate multi-step workflows", judged on "level of autonomy ... effectiveness ... practical usefulness"; Creative $5K for "the most original and compelling creative project built using Muse Image or Muse Wonder".

## Where we stand today (what the video shows)
- One Chat Completions call per message to `muse-spark-1.3` Standard (`lib/llm/meta.js`): `response_format: json_schema` (`strict: false`), `reasoning_effort: low` (measured ~930 thinking tokens, 4.7 s; 2,950 / 11.5 s at default), redacted message + compacted life context + pattern cards + detector evidence in, a 13-field verdict with evidence enums out, two-way guardrail, language check, per-user cache, circuit breaker. Screenshots: image data URL → JSON transcription → the same pipeline (`extractFromImage`). Threat feed: Muse turns IC3 and cybermalveillance alerts into candidate pattern cards that only a human activates (`extractPatternCard`). The card prints "Judged by Muse Spark (muse-spark-1.3)" and `latency_ms`.
- Not used: Responses API, reasoning summaries, function tools, `web_search`, Muse Voice Transcribe, SAM 3.1, Muse Image, video or PDF input, open weights, Prompt Guard; prompt caching is automatic (`cached_tokens`) but never surfaced. The Android pre-screen is regex (`RegexPreScreener`; `PreScreeners.current` is the swap point).
- As a judge would score it: a careful basic integration with two real touches (the guardrail overrules the model; a schema with evidence kinds), about 6/10. The field already stacks models: TrueTick (Spark + SAM 3.1, voice note, QR), Grandma Buddy (Spark + Voice Transcribe), Krai-A (Spark + Wonder + Voice). "We also transcribe voice" is table stakes; nobody in the scam field claims verifiable tool use, reasoning summaries or open-weight parity numbers.
- Already in hand, just say it on screen: the guardrail line, the effort and latency numbers, the `max_tokens` finding ("at 900 tokens it spent the whole budget thinking and answered nothing"), 0/250 false Scam, Standard mode.

## Recommendation (in order)
1. **Responses API + reasoning summary + "Checked:" chips (1 day, Oct 29, Vlad).** Add a `meta-responses` provider in `lib/llm` (`POST /v1/responses`, `instructions` + `input`, `text.format` json_schema, `reasoning: {effort: "low", summary: "concise"}`, `store: false`), keep Chat Completions as the fallback and the cache key unchanged; show the summary on the guardian page and in the audit list, never on the senior card; derive "Checked:" chips from the evidence kinds already on each reason. Video line: "Muse Spark on the Responses API: a strict schema, and its reasoning in brief for the family. Never raw chain of thought."
2. **Investigate, the verifiable agent (2 days, Oct 30–31, cut on Nov 1 if unstable).** The same provider with function tools over code that exists (`src/links/resolver.js` RDAP and URLhaus, `lib/context.js` lookups that return relations and counts only, `lib/patterns.js`) plus `web_search` with `user_location`; at most six tool calls, arguments validated, every tool result rendered as a line on the card, reasons must reference a line, guardrails applied after. Behind a button on Be careful cards and in Check something else; the inbox path stays one-shot and measured. Video line: ten seconds of the trace filling in, then "every reason points to a check you can see".
3. **Prompt Guard 2 shield (0.5 day, Oct 29, Vlad).** Chunk at 512 tokens, call the Groq-hosted 86M model (or a sidecar), add an `ai_instructions` signal to the detector with the senior wording, add the hidden-text seed case to demo mode. Video line, 6 s: "Two Meta models: one judges, one guards the judge."
4. **Voice-note check (1 day, Oct 30, Hadrien if the script is done by noon; else Vlad on Nov 1 morning, or cut).** `/api/check/audio` accepting WAV (webm via ffmpeg when present), `muse-voice-transcribe-1.0`, transcript → `checkMessage` with channel "voice" (the schema's channel enum grows), a seeded 15 s "it's Ethan" note in demo mode. Video line, 10 s: "Voice scams hurt most; Muse Voice Transcribe turns the note into evidence."
5. **Open-weights mode and the faithfulness grader (1 day, Oct 31, Vlad, credits permitting).** Apply for Baseten credits on Oct 28; run `make score` and `eval-corpus --muse --sample 50` with `LLM_PROVIDER=openai-compatible`; publish both tables in the README; run the grader over the cached 500 verdicts. Decide on Oct 31 whether the public demo itself runs on Spark Open (then the open-weights bonus is a real claim). Video: one line on the numbers card.
If time remains: 7 (PDF invoice, 0.5 day) before 8 (video check); never 9–13.

## What not to do
- No on-device Glimmer claim: keep the regex gate and call it "on-device rules"; the only honest Glimmer story is Meta's "local agent that asks first" on a PC, not a senior's phone.
- No Muse Image "what the real email looks like": generating a brand's email is impersonation by us and teaches a look, not a check.
- No model stacking for its own sake: at most four Meta surfaces in three minutes, each labelled and doing product work; a modality without a senior story reads as "we also call X".
- No tool agent on the inbox path (latency, unmeasured accuracy); no Wonder for live checks (3–5x the cost, no visible gain); no Contributor mode for cheaper sweeps (refused in code, privacy promise).
- No live call listening in the video (article 226-1, all-party states); the voice-note file path tells most of the story.
- No "zero retention" claim for the Model API; Voice Transcribe lists a ZDR option at Standard price (terms unverified).
- No raw JSON for more than 4 s, no SAM mask as decoration, no Muse Code beyond one README line (and only if it was used).
