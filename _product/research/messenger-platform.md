# Messenger Platform: what the Prudence Page can do tonight

Checked against Meta's developer documentation on 2026-11-04 for `specs/messenger-channel.md`. Meta moved the Messenger docs under `developers.facebook.com/documentation/business-messaging/messenger-platform` (M below); most of the old `/docs/messenger-platform/...` pages no longer render.

## Findings
- Webhook body: `{"object":"page","entry":[{"id","time","messaging":[{"sender":{"id":"<PSID>"},"recipient":{"id":"<PAGE_ID>"},"timestamp","message":{"mid","text"}}]}]}`; several entries per delivery, one event per `messaging[]` item. Attachments: `message.attachments[].type` in `audio`, `file`, `image` (gifs too), `sticker` (its own type since Aug 30, 2026, with `payload.sticker_id`), `video`, `fallback` (a shared link, sometimes with no payload), `reel`, `ig_reel`, `post`, `ig_post`, `appointment_booking`; the file is at `payload.url`. Replies carry `message.reply_to.mid`. No forwarded flag anywhere: a forward looks like an ordinary message (unverified by a live event).
- Echoes of the Page's own replies (`message.is_echo`) arrive only when the `message_echoes` field is subscribed; subscribing `messages` alone keeps them out.
- Handshake: GET with `hub.mode=subscribe`, `hub.verify_token`, `hub.challenge`; answer the challenge or 403. Signature: `X-Hub-Signature-256: sha256=<HMAC-SHA256 of the raw body bytes with the App Secret>`, lowercase hex; hash the bytes as received, never re-serialised JSON. Answer 200 within 5 s; after an hour of failures Meta unsubscribes the app; retries run for 36 hours, so deduplicate on `mid`. **Seen on Nov 4** (the Hey Prudence app, through a quick tunnel): the handshake GET arrived within a second of Verify and save and carried both `hub.mode`/`hub.verify_token`/`hub.challenge` and `hub_mode`/`hub_verify_token`/`hub_challenge` in the same query string; a handler reading the dotted names answered it, before any Page was connected.
- Send API: `POST https://graph.facebook.com/v26.0/{PAGE_ID}/messages` (Meta's samples also use `me/messages`), body `{"recipient":{"id":"<PSID>"},"messaging_type":"RESPONSE","message":{"text":"…"}}`; `messaging_type` in `RESPONSE`, `UPDATE`, `MESSAGE_TAG`, `UTILITY`; inside the 24-hour window the person's message opens. Text under 2,000 UTF-8 characters (seen only in a search snippet of the old Send API reference; unverified on the live page). The token: the docs show `?access_token=`; an `Authorization: Bearer` header is what Meta's WhatsApp docs use on the same host (unverified for Messenger until the first live send).
- Typing dots: `{"recipient":{"id":"<PSID>"},"sender_action":"typing_on"}` to the same endpoint, alone in its request; off by itself after 20 s or when a reply goes out. `typing_off` and `mark_seen` exist.
- Attachment download: nothing documented about tokens, hosts or expiry. Seen in practice (no source): signed CDN links on `scontent.xx.fbcdn.net`, `video.xx.fbcdn.net`, `cdn.fbsbx.com`, no token needed, an `oe=` expiry; `lookaside.fbsbx.com` is the Instagram and WhatsApp media host. Download as soon as the webhook arrives (unverified).
- Who can talk to the Page before App Review: "Page tokens only allow your Page to interact with Facebook accounts that have been granted the Administrator, Developer, or Tester role" (Roles tab). Standard Access is automatic for Business apps and covers role holders; up to 50 testers (500 with a verified business); testers can be ordinary Facebook users, Administrators and Developers need a developer account. The webhook prerequisites say to publish the app ("Go live") and to have Standard Access "to receive notifications from people who have a role on your app"; App Review (`pages_messaging`, Advanced Access) only for people without a role. Whether the Page itself must be published: not stated (unverified). The Page token must come from someone with the `MODERATE` task on the Page (to subscribe) or `MESSAGING` (to send). **Seen on Nov 4:** going Live is the "Publish" item of the new dashboard's left menu (there is no App Mode toggle at the top); it needs a Category and a Privacy policy URL in App settings → Basic, and Meta fetches that URL at Publish: an unreachable host got "Invalid Privacy Policy URL", a reachable one went through. No business portfolio was needed. The app's creator is its Administrator (Testers 0 of 50).
- Dashboard steps (use case "Engage with customers on Messenger from Meta" → Messenger API Setup): Configure webhooks (callback URL over https with a valid certificate, verify token); Generate access tokens (Connect → select the Page → Continue → Save); Add Subscriptions (tick `messages`, Confirm). Alternative: `POST /{PAGE_ID}/subscribed_apps?subscribed_fields=messages` (needs `pages_messaging` and `pages_manage_metadata`). **Seen on Nov 4:** the menu is now Use cases → Customize → "Messenger API Settings", three numbered steps (1. Configure webhooks, 2. Generate access tokens, 3. Complete App Review) plus Advanced; Connect opens a Facebook Login popup window (continue as the account, tick the Page, Save); Add Subscriptions opens "Edit Page Subscriptions" listing every field; Generate opens "Token Generation" (tick "I understand", the token masked, a Copy button). The token generated there carries only `pages_messaging`: `GET /me?fields=id,name` and `GET /{page-id}/subscribed_apps` answer error 100, so the `subscribed_apps` alternative is not open to it. The `{PAGE_ID}` the Graph API knows is the number under the Page name in that table, not the `profile.php?id=` number of the Page's address bar.
- Forwarding into a Page chat from the Messenger app: Forward exists (Options → Forward on the web; long-press → More → Forward on mobile) with a limit on how many chats at once; Pages as targets are not mentioned (unverified: test on the phone first; fallback a screenshot or the pasted words).
- Graph API: v26.0 is the latest (July 29, 2026); a call without a version uses the app's "Upgrade API version" setting, so every URL names the version.
- Instagram DMs, the next step: Instagram API with Instagram Login, scopes `instagram_business_manage_messages` and `instagram_business_basic` on `graph.instagram.com`; a professional account (`account_type` `Business` or `Media_Creator`); webhook `object: "instagram"`, field `messages` (echoes included; gifs and stickers send no webhook); the person's toggle is Instagram Settings → Messages and story replies → Message controls → Connected Tools → Allow Access to Messages; Standard Access covers accounts the team owns or manages, testers need a role on the app and on the account, and the app must be Live to receive notifications (Advanced Access listed for Instagram Login: unverified whether it is needed for role holders).
